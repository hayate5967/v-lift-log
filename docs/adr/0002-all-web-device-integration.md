# ADR-0002: デバイス連携は「全部Web」方式とし、ネイティブアプリと BLE を採らない

- ステータス: 採用
- 日付: 2026-08-04

## 背景

計測デバイス（ESP32）で測ったレップ数・速度を、どうやってユーザーの記録に届けるかを決める必要があった。
素直に思いつくのは「スマホアプリが BLE でデバイスと直接つながる」構成だが、
利用者は部員全員で、iPhone ユーザーも多い。

## 決定

デバイスはバックエンドに HTTP で直接つなぐ。ユーザーとの接点はすべて Web（ブラウザ）で完結させる。
ネイティブアプリと BLE は採用しない。

## 理由

- **iOS Safari は Web Bluetooth に非対応**。ブラウザから BLE 機器に直接つなぐ道が iPhone では塞がっている。
- ブラウザとローカル機器の直接通信も一般に不可。
- ネイティブアプリにすればBLEは使えるが、ストア配布・証明書・端末ごとのインストールと運用負荷が重い。
  部活で気軽に配りたいものに対して割に合わない。
- Web なら URL を共有するだけで全端末（iPhone 含む）に配布できる。
- 設定・記録・閲覧はサーバー経由で多少の遅延があっても支障がない。

## 検討した代替案

- **ネイティブアプリ + BLE**: 低遅延で直接通信できるが、上記のとおり配布と運用が重い。
- **PWA + Web Bluetooth**: iOS Safari 非対応で、対象ユーザーの半分が使えない。

## 影響

- ESP32 は自力でインターネットに出る必要がある → 接続方式の決定が必要（[ADR-0003](0003-tethering-with-wifimanager.md)）。
- プレス合図の音は**サーバーを介さずデバイス側のブザーでローカル完結**させる。
  ネットワーク遅延が入ると合図としての意味を失うため。
- 「どのユーザーの記録なのか」をデバイス側が知らない構成になるため、
  記録の帰属を解決する仕組みが別途必要（[ADR-0004](0004-session-based-record-ownership.md)）。
