# ADR-0003: ESP32 はテザリング接続とし、WiFiManager でプロビジョニングする

- ステータス: 採用
- 日付: 2026-08-04

## 背景

[ADR-0002](0002-all-web-device-integration.md) により ESP32 は自力でインターネットに出る必要がある。
利用場所は大学のジムで、使えるネットワークは大学 WiFi（eduroam）かスマホのテザリング。
またデバイスは部内の**共有物**で、日によって使う人が変わる。

## 決定

ESP32 はスマホのテザリング（通常の WPA2）に接続する。
SSID / パスワードは焼き込まず、**WiFiManager** ライブラリでプロビジョニングする。
起動時に ESP32 が一時的なアクセスポイントになり、使う人がスマホのブラウザで開く設定ページに
自分のテザリング情報を入力する。

## 理由

- eduroam は WPA2-Enterprise で、ESP32 での実装が煩雑（証明書・EAP 設定）。テザリングなら
  `WiFi.begin(ssid, password)` で済む。
- 共有デバイスなので特定の人の SSID を焼き込めない。焼き直しには PC と書き込み環境が要る。
- WiFiManager なら、使う人が自分の情報をその場で入れるだけでよく、**スマホ側の設定変更が不要**。

## 検討した代替案

- **テザリング名を固定する（例: BenchDevice）**: SSID を焼き込めるので実装は最も簡単。
  しかし **iPhone はテザリング名 = 端末名**のため、固定名にするには端末そのものを改名させる必要があり、
  iPhone ユーザーに不便を強いる。不採用。
- **eduroam (WPA2-Enterprise) に対応する**: 大学内で完結できるが実装コストが高く、
  学習の主眼（Web アプリの設計）から外れる。

## 影響

- ESP32 とスマホは同じテザリング内にいるが、通信は**直接ではなくバックエンド経由**になる。
- デバイスを初めて使う人向けに、WiFiManager の設定手順を案内する必要がある。
